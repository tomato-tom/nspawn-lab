# sFlow 実験環境
この環境は、「データプレーン（実際の通信）」と「マネジメントプレーン（監視・可視化）」を論理的に分離し、スイッチで発生したフロー情報をリアルタイムにグラフ化する一連のパイプラインを模擬しています。

### 1. ネットワークセグメントの役割

*   br0 (Management Segment: 10.0.100.0/24)
    *   監視データの収集・転送・保存・表示を行うためのバックボーンネットワークです。
    *   sFlow データグラムやメトリクスはこのセグメント上を UDP や HTTP で流れます。
*   br1 (Client Segment: 10.0.0.0/24)
    *   実験用のトラフィックを生成し、スイッチを経由させるためのデータ用ネットワークです。
    *   ここを流れるパケットが `hsflowd` によってサンプリングの対象となります。

---

### 2. 各コンテナの役割と連携フロー

#### A. データ生成・サンプリング層
*   trixie-09 / trixie-10 (Clients)
    *   `iperf3` や `tcpreplay` を使用して、`br1` 上に負荷トラフィックを生成します。
    *   送信されたパケットは `trixie-04` へ到達します。
*   trixie-04 (Switch & hsflowd)
    *   この環境の中心となる仮想スイッチです。
    *   `en1` (br1側) を通過するパケットを `hsflowd` がサンプリングし、sFlow データグラムとして `en0` (br0側) からエクスポートします。

#### B. データ収集・処理層 (Pipeline)
*   trixie-05 (goflow2)
    *   `br0` 上で待ち受け、`trixie-04` から送信されてくる sFlow データグラムを受信します。
    *   バイナリ形式の sFlow パケットを解析し、構造化されたデータ（JSON等）に変換して次の工程へ渡します。
*   trixie-06 (vector)
    *   データパイプラインのハブとして機能します。
    *   `goflow2` から受け取ったデータを整形・フィルタリングし、時系列データベースである `victoriametrics` へ効率的に書き込みます。

#### C. 保存・可視化層 (Storage & UI)
*   trixie-07 (victoriametrics)
    *   高性能な時系列データベースです。
    *   `vector` から送られてきた大量のメトリクスデータを永続化し、高速なクエリ応答を実現します。
*   trixie-08 (grafana)
    *   Web ベースのダッシュボードツールです。
    *   `victoriametrics` に保存されたデータを参照し、トラフィック量、トップトーク、プロトコル比率などをグラフとしてブラウザに表示します。

---

### 3. データの流れ

1.  発生: Client (`trixie-09`) がパケットを送信。
2.  サンプリング: Switch (`trixie-04`) がパケットを一部抜き取り、sFlow パケットを作成。
3.  エクスポート: Switch が管理系ネットワーク (`br0`) 経由で Collector (`trixie-05`) へ送信。
4.  変換: `goflow2` がパケットを解析し、`vector` (`trixie-06`) へ引き渡し。
5.  蓄積: `vector` がデータを `victoriametrics` (`trixie-07`) に保存。
6.  表示: ユーザーが `grafana` (`trixie-08`) の画面でリアルタイムの統計情報を確認。
