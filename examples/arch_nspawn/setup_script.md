# setup.sh

このスクリプト `setup.sh` は、**systemd-nspawn** を使用して軽量なLinuxコンテナ環境を構築・管理するための自動化ツールです。

主な機能
* クリーンアップ: 既存のコンテナとネットワーク設定を削除し、初期状態に戻す。
* ネットワーク構築: ブリッジの作成、NAT、ポート転送の設定。
* コンテナ起動: 設定ファイル (json) に基づいてコンテナを起動し、内部のネットワーク/DNSを設定する。

---

## 1. 事前チェックと準備
```bash
CONFIG_FILE="${1:-default.json}"
# jqコマンドと設定ファイルの存在確認
```
* 引数がなければデフォルトで `default.json` を読み込みます。
* JSONパーサーである `jq` がインストールされているか確認します。

## 2. クリーンアップ関数 (`cleanup`)
スクリプト実行前に環境を掃除します。
* コンテナ停止: `machinectl list` で動作中のコンテナを探し、すべて停止させます。
* ブリッジ削除: `group 100` を検出し、削除します。
* NATテーブル削除: `nft delete table inet nat` でファイアウォール/NATルールを完全に削除します。

## 3. ネットワーク設定関数

### `create_bridge` (ブリッジ作成)
*   `ip link add ... type bridge` で仮想スイッチ（ブリッジ）を作成します。
*   `group 100` を付与することで、後で一括削除できるようにマーキングしています。
*   ゲートウェイIP（例: `10.0.0.1/24`）をブリッジ自体に割り当て、有効化します。

### `setup_nat` (NAT設定)
* IPフォワーディング有効化: ホストマシンがルーターとしてパケットを転送できるように `net.ipv4.ip_forward=1` にします。
* nftables設定:
    * `inet nat` テーブルを作成。
    * `postrouting` チェーンで **Masquerade（マスカレード）** を設定。これにより、コンテナからの通信はホストのWAN IPに変換され、外部インターネットに出られます。
    * `prerouting` チェーンを作成。これは後のポートフォワーディング用です。

## 4. コンテナ起動関数 (`run_container`)
* systemd-nspawn起動:
    * `tmux new-window -d` を使い、バックグラウンドでコンテナを起動します。
    * `--network-bridge`: 作成したブリッジに接続します。
    * `--bind`: 指定があればホストのディレクトリをマウントします。
* 起動待ち: `machinectl shell` が通じるまでループで待ちます（最大5回）。
* 内部ネットワーク設定:
    * コンテナ内の `host0` インターフェースにIPアドレスを付与。
    * デフォルトルートをブリッジ（ゲートウェイ）に向けます。
    * DNS (`/etc/resolv.conf`) を設定します。

## 5. メイン処理の流れ

1.  WANインターフェース検出:
    * `ip route show default` から、有線 (`enp*/ens*`) または無線 (`wlp*`) のデフォルトゲートウェイ向けインターフェース名を取得します。これがインターネット出口になります。

2.  ブリッジとNATの構築 (JSONループ):
    * `default.json` の `bridges` 配列を処理します。
    * ブリッジを作成し、NATルールを追加します。
    * ポートフォワーディング: `port_forwards` が定義されている場合、WAN側の特定ポートへのアクセスを、指定されたコンテナのIP:ポートへ転送する `dnat` ルールを `nftables` に追加します。
        * 例: ホストの80番ポート → コンテナAの80番ポート

3.  コンテナの起動 (JSONループ):
    * `config.json` の `containers` 配列を処理します。
    * 該当するブリッジ名からゲートウェイIPを解決し、`run_container` を呼び出してコンテナを起動・設定します。

4.  完了表示:
    * 最後に `ip -br addr show group 100` で、作成されたブリッジのIP状況を表示して終了します。


## 必要な前提条件
このスクリプトを実行するには、以下の環境が必要です：
* root権限 (`sudo` がパスワードなし、または都度入力可能であること)。
* パッケージ: `jq`, `tmux`, `systemd-container` (machinectl/nspawn用), `nftables`。
* コンテナイメージ: systemd-nspawn用に準備されたディレクトリツリー（通常 `/var/lib/machines/<名前>` など）が既に存在している必要があります。このスクリプトはイメージのダウンロードや展開までは行いません。
* config.json: 適切な形式の設定ファイル。

## 注意点
* **破壊的処理**: `cleanup` 関数で既存の `group 100` のインターフェースや `inet nat` テーブルを問答無用で削除するため、他の重要なネットワーク設定と競合しないよう注意が必要です。
* **ハードコーディング**: WANインターフェースの検出ロジックが `enp/ens/wlp` に依存しており、特殊な命名規則のインターフェースだと検出に失敗する可能性があります。
